V4 direction

不是重做一套概念产品，而是把现有产品整理成清楚的页面系统

V3 的问题是抽象过多。V4 回到当前实现：Management 有 overview、authoring list、viewer list、datasources、settings；Authoring 是独立工作台；Viewer 是发布后的阅读页。我们只重新定义每个页面的职责、信息优先级和视觉规范。

页面只做一件主任务 Overview 看状态；Drafts 管草稿；Published 管发布；Data 管连接；Settings 管工作区和用户。
Authoring 不承载管理功能 编辑器只做创作、检查、保存、发布。数据源配置和用户管理不能挤进画布。
保留当前实现可落地性 每个功能都能映射到当前 API、state、component，而不是凭空设计。

产品主线

用户不是来“玩 AI 面板”，而是创建 dashboard/report 草稿，接入数据，检查质量，发布一个可阅读的报告。

1Management 是入口，不是创作容器。
2Authoring 从 Drafts 进入，默认独立全屏。
3Viewer 只呈现 published snapshot，不出现编辑和系统设置。
4Data / Settings 是治理页，支持创作但不干扰创作。

01 Page contracts

每个页面先有职责，再有界面

这是 V4 最重要的部分。我们先定义页面边界，后面 UI 才不会继续混乱。下面的页面名基本对应当前实现，只调整产品语义。

based on current routes implementation ready
/

Overview

主任务回答“我现在该处理什么”。
应该有总数、草稿、发布、最近报告、质量/数据待办、快捷入口。
不应该有完整编辑器、数据源表单、用户权限矩阵。
/authoring

Authoring Drafts

主任务管理 draft dashboard/report。
应该有搜索、新建、编辑、删除、版本、更新时间、草稿状态。
不应该有已发布阅读体验、schema 浏览器、workspace 用户设置。
/viewer

Published Reports

主任务管理已经发布的 reader snapshot。
应该有打开阅读页、复制链接、版本、更新时间、取消发布。
不应该有新建草稿按钮、编辑画布、AI patch 审批。
/datasources

Data Sources

主任务管理可被报告使用的数据连接。
应该有连接列表、Add Postgres/Athena、schema、引用保护、删除。
不应该有报告编辑、发布操作、AI 聊天主入口。
/settings

Settings & Users

主任务配置 workspace、用户上下文、agent/debug 行为。
应该有workspace、current user、members、verbose trace、主题/模板默认值。
不应该有schema 细节、报告列表、画布编辑。
/authoring/:id

Authoring Studio

主任务编辑一个 draft，并通过 AI/检查流推进到 publish。
应该有画布、Desktop/Mobile、Undo、Run check、Save、Publish、Preview、AI dock、advanced drawer。
不应该有全局数据源创建表单、用户管理、发布列表。
/viewer/:id

Viewer

主任务稳定阅读发布报告。
应该有报告封面、筛选、图表、数据说明、导出/分享。
不应该有保存、发布、AI dock、字段编辑。
future

Request Context

主任务UI 展示当前上下文，但不让用户伪造上下文。
应该有workspace/user 显示、权限状态、server resolved context。
不应该有客户端直接提交可信 user/workspace。
